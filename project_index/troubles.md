# troubles.md

> 用途：记录反复出现的问题与标准处置，避免新线程重复踩坑。

## T-001 中文协作与编码问题（长期约束）
- 状态：长期生效
- 严重性：高
- 问题描述：用户惯用中文，但历史上多次出现编码写坏/乱码，导致文档不可交接。
- 已知触发方式：
  - 非 UTF-8 编码写入。
  - Shell 写入时字符串转义污染（如反引号被解释）。
- 处理规范：
  1. 所有索引文档统一 UTF-8 编码。
  2. 每次写入后抽样读取关键文件，确认中文可读。
  3. 变更说明优先中文，英文术语保留原词并给中文语义。
- 验收方式：
  - `Get-Content` 抽样无乱码。
  - 关键关键词（发布版/内部版/版本号/TODO）可直接检索。

## T-002 ROOT 指针漂移事故
- 状态：已修复，需防复发
- 严重性：S0
- 现象：active 子桶治理后 ROOT 被错误重定向。
- 根因：ROOT 与 active 更新逻辑耦合。
- 处置：拆分更新条件，并补充稳定性测试。
- 防复发动作：任何触及“source->successor 切换”的改动都必须跑指针测试。

## T-003 fallback 来源错标
- 状态：已修复，需持续检查
- 严重性：高
- 现象：本地 rerank fallback 结果标记为 llm。
- 根因：source 字段赋值沿用主路径默认。
- 处置：按路径显式赋值。
- 防复发动作：检查 `result_source` 与每条 `matches[].source` 一致性。

## T-004 大文本压测超窗风险
- 状态：持续跟踪
- 严重性：高
- 现象：批量 add_dir 后 optimize/split 输入可超过窗口上限。
- 影响：治理工具失败，可能形成“死桶/死循环式治理失败”。
- 当前结论：
  - 触发统计应尽量基于真实 token。
  - split fallback 必须保证可拆生效。
  - optimize 不应注入无必要 context payload。


## T-006 BOM 与终端编码误判
- 状态：已识别，长期防护
- 严重性：中高
- 问题描述：文档虽然是 UTF-8，但在 Windows PowerShell/终端下若编码未显式设置，可能被按 ANSI/本地代码页解释，表现为“看起来乱码”。
- 典型现象：
  - 文件在 IDE 可读，但终端 `Get-Content` 输出乱码。
  - 反复误判“文件写坏”，造成无效返工。
- 约束规则（必须执行）：
  1. 使用 Shell 前先显式设置 UTF-8 环境：
     - `$OutputEncoding = [Console]::OutputEncoding = [System.Text.UTF8Encoding]::new($false)`
     - `chcp 65001 > $null`（Windows 终端场景）
  2. 文档落盘统一 UTF-8（建议 BOM 以提升 Windows 识别稳定性）。
  3. 写入后必须抽样复读至少 2 个文件，确认中文可读。
- 验收方式：
  - 终端与 IDE 对同一文件显示一致。
  - 关键文档（`introduction.md`、`work_history.md`）无乱码。
