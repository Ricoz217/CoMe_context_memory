# assumptions.md

## 1. 用户协作假设
- 用户主要使用中文交流与评审。
- 用户更重视“根因正确”而非“现象看似变好”。
- 用户接受先在内部版实验，再同步到发布版。

## 2. 开发偏好假设
- 先排查再修改，尽量避免盲改。
- 修复应带最小可复现与回归测试。
- 同步发布时要考虑文档可读性和对外可交付性。

## 3. 运行与使用假设
- 同一 memory base_dir 默认单写者模型。
- 多接口并用时建议统一由一个服务进程承担写入。
- 大文本场景是常态压力源，治理逻辑需长期关注。

## 4. 默认策略
- 默认语言：中文。
- 默认编码：UTF-8。
- 默认记录粒度：里程碑级（非流水账）。
- 默认同步路径：内部版先验证 -> 发布版再同步。

## 5. 非目标（当前阶段）
- 不做 LLM WIKI
- 不做 分布式锁/多进程锁 

## 6. 偏离处理
- 若必须偏离默认策略，需在 `work_history.md` 记录原因与影响。
- 若偏离导致问题，需在 `troubles.md` 追加复盘条目。

## 7. 会话前缀协作约定（新增）
- `# QA`：表示用户在询问项目代码问题。
- 执行要求：
  - 回答必须以代码与现有索引为依据，优先给出可核验结论。
  - 若存在不确定性，必须明确标注“不确定”以及不确定原因，不得伪确定。
- `# TODO`：表示用户要新增 TODO 事项。
- 执行要求：
  - 必须将事项写入 `project_index/TODO.md`。
  - 写入格式需包含：`【已完成】`、`目标版本`、`优先级`、`版本归属`、`背景`、`目标`、`验收标准`。
